# 투자 포트폴리오 설계 및 성과평가 · 라이브 웹앱

가상 투자금 1,000만원으로 6주간 실제 매매를 기록하는 수업용 앱입니다.
학생은 휴대폰으로 주문을 넣고, 교수는 화면 하나로 반 전체를 통제합니다.

---

## 1. 파일 구성

| 파일 | 역할 |
|---|---|
| `app.py` | 메인 앱 (학생 화면 + 교수 통제소) |
| `universe.py` | 승인 종목 리스트 46종 — 여기만 고치면 선택지가 바뀝니다 |
| `price_fetcher.py` | 종가·환율 수집. `requests` 만 씁니다 (pykrx·yfinance 불필요) |
| `supabase_schema.sql` | Supabase 테이블 정의 (`inv_pf_` 접두어) |
| `requirements.txt` | 패키지 목록 |
| `.streamlit/secrets.toml.example` | 로컬 실행용 비밀키 예시 |

## 2. 설치 순서

### (1) GitHub

새 저장소를 만들고 위 파일을 전부 올립니다. **`secrets.toml`은 절대 올리지 마세요.**
`.gitignore`가 이미 막아두었습니다.

```bash
git init
git add .
git commit -m "투자 포트폴리오 웹앱"
git branch -M main
git remote add origin https://github.com/사용자명/저장소명.git
git push -u origin main
```

### (2) Supabase

1. [supabase.com](https://supabase.com) 에서 새 프로젝트 생성
2. 왼쪽 메뉴 **SQL Editor** → **New query**
3. `supabase_schema.sql` 내용을 통째로 붙여넣고 **Run**
4. 왼쪽 메뉴 **Project Settings → API** 에서 두 값을 복사

   - **Project URL** → `SUPABASE_URL`
   - **anon public** 키 → `SUPABASE_KEY`

### (3) Streamlit Cloud

1. [share.streamlit.io](https://share.streamlit.io) → **New app**
2. GitHub 저장소 선택, Main file path 는 `app.py`
3. 배포 후 앱 화면 우측 하단 **⋮ → Settings → Secrets** 로 들어갑니다

## 3. Streamlit Secrets 입력 방법

Secrets 창에 **아래 세 줄을 그대로** 붙여넣고 Save 를 누릅니다.
따옴표를 반드시 포함해야 하고, 등호 좌우 공백은 있어도 없어도 됩니다.

```toml
SUPABASE_URL = "https://xxxxxxxxxxxx.supabase.co"
SUPABASE_KEY = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9....."
PROF_PW = "3383"
```

주의할 점

- `SUPABASE_KEY`는 **anon public** 키를 씁니다. `service_role` 키는 절대 넣지 마세요.
- 저장하면 앱이 자동으로 재시작합니다. 30초쯤 기다리면 됩니다.
- `PROF_PW`는 교수 통제소 비밀번호입니다. 학생에게 알려주지 마세요.
- 로컬에서 돌려볼 때는 `.streamlit/secrets.toml` 파일을 만들어 같은 내용을 넣습니다.

## 4. 주간 운영 순서

라운드 구성은 다음과 같습니다.

| 라운드 | 주차 | 수업일 | 내용 |
|---|---|---|---|
| 1 | 7주 | 10/12 (월) | 최초 매수 |
| — | 8주 | 10/19 | 중간고사 (매매 없음) |
| 2 | 9주 | 10/26 | 1차 리밸런싱 |
| 3 | 10주 | 11/2 | 2차 리밸런싱 |
| 4 | 11주 | 11/9 | 3차 리밸런싱 |
| 5 | 12주 | 11/16 | 4차 리밸런싱 (마지막) |
| 6 | 13주 | 11/23 | 최종 결과 확인 |

### 월요일 수업 시작 전 (5분)

1. 교수 통제소 접속
2. **[📥 전일 종가 불러오기]** — 20~40초 걸립니다. 학생들의 평가금액이 갱신됩니다
3. 라운드를 이번 주 번호로, 단계를 **주문접수**로 바꾸고 **[적용]**

### 수업 중

학생들이 자기 휴대폰으로 접속해 현황을 보고 주문을 냅니다.
**📋 이번 라운드 제출 현황**에서 미제출자를 확인할 수 있습니다.

### 수업 종료 시

단계를 **체결대기**로 바꿉니다. 이때부터 주문을 받지 않습니다.

### 화요일 밤

1. **[📥 전일 종가 불러오기]** — 기준일을 화요일로 지정
2. **[⚙️ 이 라운드 체결하기]** — 화요일 종가로 전원 체결.
   체결과 동시에 평가금액이 자동으로 다시 계산되므로 추가 작업이 없습니다.
3. 단계를 **체결완료**로

> 보유내역만 바뀌고 시세는 그대로일 때는 **[🔄 평가금액만 다시 계산]** 을 쓰세요.
> 외부 시세를 받지 않아 즉시 끝납니다.

### 기준일은 앞으로만 진행하세요

체결가와 평가금액 자체는 날짜 순서와 무관하게 계산됩니다.
다만 학생 화면의 수익률 그래프와 교수 화면의 최대낙폭·변동성은 **날짜순으로 정렬**되므로,
이미 저장된 기준일보다 과거 날짜를 나중에 넣으면 그래프가 뒤엉킵니다.
그런 날짜를 고르면 경고가 표시됩니다. (테스트 중에는 무시해도 됩니다.)

---

## 5. 부정 방지 장치

- **체결가는 주문 시점에 알 수 없습니다.** 주문은 수업 중에 받고 체결은 다음 종가로 합니다.
  지나간 저점을 골라 적어도 아무 이득이 없습니다.
- **제출은 라운드당 한 번, 수정 불가.** 제출 시각이 DB에 자동 기록됩니다.
- **주문 전에 심정을 먼저 적게 합니다.** 이 칸을 채워야 주문 화면이 열립니다.
  숫자는 사후에 복원할 수 있지만 그때의 판단은 복원할 수 없습니다.
- 비중 제한(단일 30% · 고위험 20% · 종목 4~7개)은 제출 단계에서 자동 검증됩니다.

---

## 6. 네트워크 부하

의도적으로 아주 낮게 유지했습니다.

- **자동 새로고침·폴링이 전혀 없습니다.** 모든 갱신은 버튼을 눌러야 일어납니다.
- DB 조회 결과는 10분간 캐시됩니다. 슬라이더를 움직여도 DB를 다시 읽지 않습니다.
- 외부 시세 API는 **[기준가 업데이트] 버튼에서만** 호출됩니다. 주 2회, 회당 20회 안팎입니다.
  (국내는 전종목을 2회 요청으로 일괄 수신하므로 종목을 늘려도 요청 수가 늘지 않습니다.)
- 체결과 스냅샷 저장은 전체를 모아 한 번에 upsert 합니다.

## 7. 학생 화면

1. 나의 현재 포트폴리오 (평가금액 · 수익률 · 종목별 비중)
2. 이번 라운드 주문 (심정 → 주문 → 이유 순서)
3. 나의 6주 기록 (수익률 그래프 + 라운드별 심정·이유·체결내역)
4. **나의 매매 기록 내려받기** — CSV 한 가지.
   거래내역 각 줄에 그 라운드에 본인이 적은 심정과 결정 이유가 함께 붙어 있습니다.
   보고서 초안은 제공하지 않습니다. 기록만 주고 해석은 학생이 직접 하도록 했습니다.

학생 화면에는 **순위가 나오지 않습니다.** 다른 학생의 수익률도 보이지 않습니다.

---

## 8. 교수 화면의 반 전체 성과

- **익명 산점도** — 가로축 최대낙폭 또는 주간변동성, 세로축 수익률.
  점 하나가 학생 한 명이고 이름은 없습니다. 순위표 대신 이 화면을 스크린에 띄우세요.
- **수익률 분포** — 이름 없는 히스토그램
- **매매 행태** — 매매 횟수 분포, 많이 매매한 절반 vs 적게 매매한 절반의 평균 수익률,
  가장 많이 매매된 종목. 11주차 행동재무 수업 재료입니다.
- **학생별 표** — BIT 유형·매매횟수·수익률·최대낙폭. 교수 화면에만 나옵니다.
- **라운드별 학생 기록** — 이름을 가린 채 심정과 이유를 훑어볼 수 있습니다.

## 9. 학기 종료 · 테스트 후 정리

교수 화면 맨 아래 **⚠️ 데이터 관리** 를 펼치면 됩니다.

1. 먼저 **[📥 이 분반 전체 데이터 내려받기]** 로 백업하세요. 되돌릴 수 없습니다.
2. 초기화 범위를 고릅니다.
   - 기본: 현재 분반의 주문 · 라운드기록 · 평가금액 · 학생명단
   - **[종가 데이터도 함께 삭제]** — `inv_pf_prices` 전체를 지웁니다. **세 분반이 공용으로 쓰므로**
     다른 분반이 진행 중이라면 체크하지 마세요.
   - **[세 분반 전체를 초기화]** — 인하대·숙대1·숙대2 를 한 번에 정리합니다.
3. 확인란에 분반 이름을 입력해야 버튼이 활성화됩니다.

테스트를 마치고 실제 학기를 시작하실 때는 **두 체크박스를 모두 켜고** 한 번 실행하시면
Supabase 를 직접 건드리지 않아도 깨끗해집니다.

## 10. 자주 겪는 문제

**학생이 "열려 있는 강의실이 없습니다"를 본다**
→ 해당 분반의 단계가 `대기`입니다. 다른 단계로 바꾸세요.
분반 두 곳이 동시에 열려 있어도 같은 오류가 납니다. 한 곳만 여세요.

**기준가 업데이트에서 일부 종목이 실패한다**
→ 휴장일이거나 해당 소스에서 지원하지 않는 종목입니다.
국내 종목은 KRX 일괄 조회가 실패해도 네이버 금융으로 자동 보충됩니다.
**9월 중에 임의 날짜로 미리 한 번 눌러보시고, 그래도 실패하는 종목은 `universe.py`에서 빼두세요.**

**수집 성공 메시지가 사라졌다 — 데이터가 날아간 건가**
→ 아닙니다. Streamlit 은 화면의 위젯을 건드릴 때마다 스크립트를 다시 실행하는데,
성공 메시지는 버튼을 누른 그 순간에만 그려집니다. 저장된 값은 Supabase 에 그대로 있습니다.
**기준가 업데이트 항목 맨 위의 현황 패널**(저장된 기준일 · 저장된 종가 · 적용 환율)이
DB 를 직접 읽어 항상 표시되므로, 그 숫자로 확인하시면 됩니다.

**해외 종목만 전부 실패한다**
→ 야후·Stooq 가 모두 막힌 경우입니다. 교수 화면의 **[✍️ 종가 직접 입력]** 을 펼치면
실패한 종목이 자동으로 채워져 있습니다. 해당 날짜 종가를 보고 그대로 넣고 저장하면
평가금액이 다시 계산됩니다. 해외 종목은 **달러 가격 그대로** 넣으면 됩니다.

**환율만 실패한다**
→ 직전에 저장된 환율을 자동으로 재사용합니다. 첫 회차라 저장값이 없으면
[종가 직접 입력]에서 환율만 넣어 저장하세요.

**"pykrx 미설치" 또는 패키지 설치 오류가 난다**
→ 이 버전은 `pykrx`·`yfinance` 를 쓰지 않습니다. `requirements.txt` 에 네 줄
(`streamlit`, `pandas`, `supabase`, `requests`)만 있는지 확인하고,
Streamlit Cloud 에서 **Manage app → Reboot** 하세요.

**체결 버튼을 눌렀는데 "기준가가 없습니다"**
→ 기준가 업데이트를 먼저 실행해야 합니다. 체결은 마지막으로 불러온 종가를 씁니다.

**학생 화면이 갱신되지 않는다**
→ 실시간 갱신이 없는 설계입니다. 학생에게 **[🔄 화면 새로고침]** 을 누르라고 안내하세요.

**첫 실행이 느리다**
→ Streamlit Cloud 무료 플랜은 접속이 없으면 앱이 잠듭니다.
수업 10분 전에 한 번 접속해 깨워두세요.
